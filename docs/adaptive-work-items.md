# Adaptive work-item execution

The bug pipeline can optionally split a newly planned implementation batch into a small dependency graph of bounded work items. The runtime API defaults to delegation disabled; the GitHub controller workflow opts new intake into adaptive delegation. Set `CLINICOS_WORK_ITEM_DELEGATION=off` to disable hosted delegation, or `adaptive` to enable it explicitly; `CLINICOS_WORK_ITEM_PARALLEL` accepts `1` or `2` and defaults to `2`. A graph can contain at most eight nodes. The planner maps every node back to the already accepted batch scope, tasks, acceptance criteria, and verification commands. The controller checks dependencies and file/resource conflicts, reserves work before inference, integrates child changes in order, and then runs the existing verification and independent QA gates.

This applies only when the pipeline creates a new plan for new work and only to that plan's first initial implementation attempt. Existing plans, persisted batch state, and in-flight work remain frozen and are not rewritten or decomposed. Normal implementation handles legacy batches and adaptive mode being off. A definite blocked graph can use a later authorized senior parent attempt; invalid graphs, unknown outcomes and retained Git conflicts stop without hidden replay. Dynamic decomposition does not extend authorized issue scope or change attempt budgets, release gates, review policy, or exact-SHA protections.

## Executors and availability

Codex remains the configured senior executor and can use the configured delegate model for suitable bounded tasks. A personal local Claude Code Max profile is an optional additional delegate, enabled only with `CLINICOS_CLAUDE_EXECUTOR_ENABLED=true` and explicit executable, personal configuration directory, and model settings. Its adapter is restricted to file tools (`Read`, `Edit`, `Write`, `Glob`, `Grep`), has no shell, web, agent, or MCP tools, and cannot run in GitHub Actions. The local Claude profile is separate from the existing independent peer-review flow. The review watcher remains a reviewer; it does not execute work items.

The controller checks configured profiles and CLI/auth capabilities before routing. That preflight reports availability only; it does not prove that a model can successfully infer on a task or that a subscription will remain available. Successful inference and lower cost or elapsed time are not guaranteed. The Claude adapter uses the personal local subscription path; this feature does not add Anthropic API execution, copy API secrets, or introduce a hosted Claude executor. Local authentication and successful inference have not been verified by this documentation change.

Hermes is not required. This feature uses the existing pipeline controller, Codex CLI, and the optional local Claude CLI adapter. The reviewed GitHub controller workflow opts new intake into adaptive mode; the repository variable `CLINICOS_WORK_ITEM_DELEGATION=off` disables that choice. These files take effect after their normal reviewed merge into the default branch and do not enable paused workflows or change existing active work. Existing integrated verification and independent peer review remain required for completed work.

For optional local Claude execution, configure `CLINICOS_CLAUDE_EXECUTOR_ENABLED=true`, an absolute native `CLAUDE_CLI_PATH`, an existing external personal `CLINICOS_CLAUDE_EXECUTOR_CONFIG_DIR` (or the existing local `CLINICOS_CLAUDE_CONFIG_DIR` alias), and `CLINICOS_CLAUDE_EXECUTOR_MODEL` (default `haiku`). Run the existing controller locally with `CLINICOS_WORK_ITEM_DELEGATION=adaptive`. The adapter requires CLI support for the restricted flags and `auth status --json` reporting a logged-in Claude.ai Max profile. It verifies capabilities without an inference probe. The controller enforces a ten-minute default session timeout, bounded output and one reserved session per graph node. The controller currently bounds sessions by timeout and output, rather than a turn count. The adapter additionally supports `--max-turns` only when the caller explicitly supplies a bounded `maxTurns` and the installed CLI advertises that flag; the current CLI configuration does not supply it. The controller runs tests separately; Claude's file-only worker cannot execute them.

## Shared Agent Skills

The repository includes the pinned Matt Pocock Agent Skills selection documented in `docs/agents/matt-pocock-skills.json` and attributed under its MIT license in `docs/agents/matt-pocock-LICENSE.txt`. These are project-local copies under `.agents/skills/`, with manual updates. The shared domain, issue-tracker, and triage-label configuration lives in `docs/agents/`. Skill installation does not enable adaptive delegation or change GitHub labels.

Definite child failures now retain an exact owned output checkpoint. The diagnostic exporter
archives only bounded, sanitized text source from definitely failed graphs, including committed
siblings that were not integrated. Unknown calls, uncertain commits and running integration
records remain non-exportable/non-replayable. The canonical authorization history digest also
binds the complete work-item graph/reservation/result envelope; no-graph legacy bindings stay
unchanged. This retention does not mark an attempt successful or authorize another inference.
