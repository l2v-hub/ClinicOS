# Standalone PR review subjects

The trusted-main handoff CLI supports explicit review-only adoption of an existing PR. Normal bug batches retain their identity, plan, editable-file and release guards. A standalone subject lives in `standaloneReviews` in the existing CAS state file; its real PR number is never used as a source issue. Only an authenticated authorized maintainer can adopt or revise it.

Run the CLI from trusted reviewed main, never from a PR checkout:

```sh
node agent-team/src/bug-pipeline/review-handoff-cli.mjs adopt --pr N --manifest /absolute/manifest.json
node agent-team/src/bug-pipeline/review-handoff-cli.mjs request --pr N
```

The maintainer supplies a bounded JSON manifest with these exact top-level fields:

```json
{
  "schemaVersion": 1,
  "repository": "l2v-hub/ClinicOS",
  "pr": { "number": 81, "url": "https://github.com/l2v-hub/ClinicOS/pull/81" },
  "sha": "CURRENT_HEAD_SHA_40_HEX",
  "baseSha": "FROZEN_PR_MERGE_BASE_SHA_40_HEX",
  "baseRef": "main",
  "branch": "feature/actual-branch",
  "issues": [],
  "packet": { "path": "artifacts/task-validation/standalone-pr-81", "files": {} },
  "sourceManifest": [],
  "implementation": [],
  "reviews": [],
  "reviewLedger": null,
  "reviewReports": {},
  "releaseHold": "Preserve existing release/deployment hold"
}
```

`packet.files` maps every tracked relative file in that packet to its SHA-256 content digest. Required files are task-contract.md, analysis.md, implementation-plan.md, validation-report.md and imported-history.json. Each imported implementation attempt requires its original contiguous round, status, historical `subjectSha` and `evidence` (a frozen relative packet file). Preserve original fields and evidence; do not replace actual history with a count. The default allowance is four implementation attempts and four review rounds. Only an authenticated maintainer command can append a one-at-a-time durable extension; a PR manifest cannot grant one. Original attempts, report bytes and ledger max_rounds metadata remain unchanged. A failed/blocked uncommitted historical attempt may honestly have `subjectSha: null`, `uncommitted: true` and its actual `sourceManifestSha256`; a passed attempt requires a real tested commit.

`baseSha` is the frozen PR merge base, authenticated through GitHub compare against the current native main tip and pinned head. Main may advance while that merge base stays unchanged; changed review ancestry fails closed. `sourceManifest` contains the full frozen merge-base-to-head tree delta outside the selected packet, including old artifact blob identities. Each entry has exactly `path`, `blob`, `mode`, `baseBlob`, `baseMode`; blob fields are Git blob OIDs, modes are 100644 or 100755. Deleted sides are null. Symlinks and submodules in the changed scope fail closed. Historical artifact bytes need not be downloaded. All non-validation-artifact Git objects and modes must match the latest passed attempt's tested commit, so evidence publication can change the head without transferring validation across source/config changes.

The committed `imported-history.json` contains `implementation`, `reviews`, `reviewLedger`, `reviewReports`, `sourceManifest`, and `packetFiles`. Its source manifest and implementation are exactly those supplied to adoption. `packetFiles` is exactly packet.files excluding imported-history.json itself. This avoids a self-referential current commit SHA; the CAS adoption record binds the final current SHA. Prior review reports and ledger must be preserved and hash-consistent. New review rounds append to the immutable imported prefix.

Nonempty native branch-required checks must all pass. The complete PR check inventory must also pass or be skipped, except the exact optional check name `Vercel`, whose failure/pending preview is explicitly tolerated. A required `Vercel` check still blocks when unsuccessful; unknown optional failures and unavailable/malformed inventories block. This policy cannot be changed by a manifest or environment flag. Forks, draft/closed PRs, changed base/head, fake or closed source issue IDs, incomplete tree inventories, packet changes and existing PR, branch or issue ownership in any durable entity collection (including manualBatches) block adoption and reservation. Ordinary adoption never transfers a manual owner or replaces its history. A new revision of the same PR requires a fresh packet path, preserves branch, issues, release hold and all historical attempts/reviews, and retains every earlier packet byte at its original path on the new head (verified through preserved packet digests); old attempt evidence copies in the new packet keep their original digests; corrections require a new tested commit and an available implementation attempt. Evidence-only head updates retain their historical tested SHA. Existing running workers cannot be replaced.

The local Claude coordinator uses the same status/claim/submit/reconcile commands. Claim consumes a CAS-reserved round before analysis. The report remains authenticated-owner, nonce, request, round and SHA bound, validated against the entire tracked head tree. Exclusive handoff labels apply to the PR only. The normal pipeline imports the comment and starts a fresh independent read-only Codex QA after clean Claude review. Neither reviewer executes PR tests, installs packages or invokes source code. Native checks and committed evidence establish execution results; the reviewers inspect their adequacy.

Findings, changed feedback or an explicitly failed owner QA stop at an orchestrator handoff. This adapter does not automate standalone source corrections. Privileged workflow/auth/tool changes remain orchestrator-owned. The infrastructure merge function requires a trusted explicit file allowlist, genuine clean Claude plus independent Codex proof, current checks, unchanged subject/feedback and no release hold, then reuses the existing exact-SHA protected merge API. Application and deployment changes fail closed at this boundary and require the verified deployment controller. The trusted main controller automatically invokes this boundary only for its fixed three test/documentation paths. The reviewer operating prompt and the regression tests pinning trust, budget and external authorization policy are protected trust roots, independently of any caller-supplied allowlist. Every controller source, policy module, agent instruction and `.github/**` path is outside automatic merge, even if a caller supplies a wider allowlist. The unrelated source-topology paths are not preauthorized. Trust-root changes remain ready for a manual protected merge and require a native current-head approving review from an independent authorized human account. The controller never manufactures that approval or uses admin merge. Same-account comment-review ownership is not an independent reviewer attestation; for otherwise eligible paths it requires a native approval from a User distinct from the author, reviewer and finalizer plus verified review protection. Classic protection or accessible active branch rules can prove that protection; 403/unavailable policy reads never prove it is absent or permit a bypass. It saves a CAS merge reservation, records the confirmed exact-SHA merge receipt, and can recover a completed merge after interruption without another review or merge. Merged subjects are terminal on subsequent ticks. No deployment, provider call or issue closure is introduced.

Installing this adapter itself requires independent QA and genuine Claude review before publication to main. Until that bootstrap is reviewed and merged, existing main cannot claim that standalone adoption is live. A prompt, queued label or fixture is not an actual Claude review or a deployment result.

The standalone-only finalizer shares that exact controller path:

```sh
node agent-team/src/bug-pipeline/review-handoff-cli.mjs finalize --pr N
```

After genuine Claude review, it invokes a separate actual Codex read-only QA session with the configured senior planner (default gpt-6.1-sol), then applies the same fixed-policy protected merge boundary. It requires an existing explicit Codex authentication directory, or an already-existing current-user .codex directory without reading/copying tokens. It never aliases CLINICOS_OPENAI_API_KEY to Codex credentials. An explicit CODEX_API_KEY is rejected before inference, including when CODEX_HOME is also present; finalizer output records authMode existing-codex-auth. Model and GitHub credentials remain separated. Runtime outputs live outside the reviewed worktree. It does not run application installation/tests or the application-execution doctor; Codex itself must support its read-only sandbox. Missing authentication, unavailable sandbox or failed QA records a block/pending ownership for explicit recovery, never a verified result. Running this tool from a candidate PR on an authenticated PC remains prohibited: first complete the independently audited source plus genuine review bootstrap and use only the resulting trusted pinned tools. Clinical release holds remain effective.

Standalone metadata is sanitized by field with an explicit two-MiB aggregate cap and bounded structure. Each retained report separately passes the existing review schema/content bound (100,000 compact JSON characters), with at most the effective audited review allowance (default four) reports, still within the unchanged aggregate cap. The adoption descriptor file and standalone report-file pre-read are bounded to512,000 UTF-8 bytes; normal batch report-file pre-read remains60,000 bytes. The final serialized review comment remains bounded to60,000 UTF-16 code units for either subject type. Stored pretty report JSON has separate150,000-code-unit/512,000-byte representation caps, while the unchanged compact review validator enforces100,000 code units. CJK and surrogate pairs are measured consistently with that validator. The normal batch100KB structured-text policy is unchanged.

Durable state saves preflight the actual pretty JSON UTF-8 payload plus512KiB for each active external-review, independent-QA or merge result at a fixed8MiB limit before any API mutation. Every writer counts reservations across normal batches, manual batches and standalone subjects; each standalone subject also includes its own reservations in its compact2MiB cap. A claim or QA that cannot reserve capacity stops before persisting a running round or starting inference. Recording the result releases its allowance atomically. This conservative backpressure keeps other writers from spending promised result space. Contents responses above1MiB may omit inline data; controller and read-only dashboard load the exact metadata-pinned Git blob, enforce file/encoding/size/base64/UTF-8 bounds and its Git blob digest, then parse JSON. Blob transport output is bounded to16MiB and CAS retains the original Contents blob SHA. Oversized or malformed state fails closed; no download URL or credentials are copied.

A pre-existing running independent Codex reservation is pending ownership. Concurrent finalize/controller calls return without changing state or labels, starting another inference, or merging. Only the owner records its model result or explicit execution failure. An existing merge reservation on a still-open PR is also pending; only a confirmed exact-SHA completed merge is recovered automatically. An authenticated maintain/admin actor can explicitly release an abandoned reservation using the audited commands below. Elapsed time alone never authorizes a retry or changes budgets.

Default state saves retain strict compare-and-swap behavior. Trusted orchestration explicitly enables at most three disjoint-entity rebases after a confirmed409. Each retry merges the original persisted base, intended change and fresh remote state into a new body; it reruns full schema/ownership/capacity validation and the original native/authentication guards. Concurrent changes to the same entity, or conflicting shared root fields, fail closed. Caller collection, entity and nested attempt references remain valid after synchronization. This is bounded best-effort persistence: exhausted retries or a same-subject conflict can still leave a durable QA reservation running after the local result could not be saved. An operator must diagnose that case; the controller never silently repeats the inference or resets a budget. Persisted diagnostics use bounded owned error codes, without raw model output, stderr or credentials.

## Audited recovery and continuation

Run the trusted pinned controller, never code from a PR comment or a candidate checkout. `status --pr N` exposes the durable SHA, active claim identifiers and recoveryTokens; these are subject guards, not credentials. New claim, QA and merge reservations have unique random identifiers; the resume token is a deterministic state fingerprint, and old undated reservations retain their legacy digest fingerprints. Each recovery requires the current durable SHA, exact reservation token and a diagnosis. The actor must have maintain/admin permission, and the CAS/native/actor guards run again at persistence. Claim/QA/merge release also requires a separately consumed verified external authorization; administrative permission or the force flag alone does not supply it.

```sh
node agent-team/src/bug-pipeline/review-handoff-cli.mjs recover --pr N --action abandon-claim --sha OLD_DURABLE_SHA --token CLAIM_ID --authorization VERIFIED_SESSION_REFERENCE --force-live --reason 'Worker confirmed stopped after head movement'
node agent-team/src/bug-pipeline/review-handoff-cli.mjs recover --pr N --action release-qa-reservation --sha DURABLE_SHA --token QA_RECOVERY_TOKEN --authorization VERIFIED_SESSION_REFERENCE --reason 'Confirmed abandoned or failed QA execution'
node agent-team/src/bug-pipeline/review-handoff-cli.mjs recover --pr N --action release-merge-reservation --sha DURABLE_SHA --token MERGE_RECOVERY_TOKEN --authorization VERIFIED_SESSION_REFERENCE --reason 'Confirmed native PR still open and unmerged'
node agent-team/src/bug-pipeline/review-handoff-cli.mjs recover --pr N --action resume --sha DURABLE_SHA --token RESUME_RECOVERY_TOKEN --reason 'Transient failure diagnosed; current identity and evidence revalidated'
```

Abandoning a claim marks its consumed review and ledger row failed and invalidates its claim identifier; it never removes the row. Head drift can be recovered administratively before new-SHA adoption. QA and merge releases archive their full prior reservations in append-only history and invalidate old approval. QA can then reserve a fresh nonce exactly once. The merge lease uses the actual GitHub command timeout (30 seconds); the QA model has a 30-minute timeout, but its surrounding Git operations have separate deadlines, so this is not an aggregate QA lease. Recovery clocks are injected. Live QA and local comment claims have no configured aggregate completion deadline, so they require verified force capability; undated/invalid legacy timestamps also fail closed without that capability. A completed failed QA is terminal and does not wait an invented lease. Trusted hosts using different operation deadlines must inject matching timeouts. `--force-live` is recorded in the authorization binding and audit history and succeeds only when the verifier grants that capability.

Merge recovery rechecks exact native identity immediately before persistence, and retains the reservation as a tombstone when the PR remains open. This prevents a merge that commits after the recovery CAS from losing its receipt: subsequent finalization still reconciles the exact reviewed head and confirmed merge SHA, without issuing another merge. A merge observed during a save guard causes stale recovery to fail; retry/reconciliation reads the retained reservation. A definite remote rejection records a visible failure while retaining its reservation; transport uncertainty is never treated as permission to repeat the write. Replays, stale tokens, actor revocation and concurrent same-entity writes fail closed. An active worker remains ownership; elapsed time only establishes lease expiration, and does not itself authorize recovery.

```sh
node agent-team/src/bug-pipeline/review-handoff-cli.mjs extend-budget --pr N --kind implementation --limit NEXT_LIMIT --authorization OWNER_INSTRUCTION_REFERENCE --reason 'Explicit owner authorization for one additional attempt'
node agent-team/src/bug-pipeline/review-handoff-cli.mjs extend-budget --pr N --kind reviews --limit NEXT_LIMIT --authorization OWNER_INSTRUCTION_REFERENCE --reason 'Explicit owner authorization for one additional review'
```

Each command appends one allowance with actor/time/nonce, original entity identity and a frozen history-prefix digest. It leaves a blocked phase in place. An exhausted normal batch with current negative published feedback can use the separate audited resume command once both implementation and review allowances are available; this does not approve feedback or skip the normal correction/validation path. It changes neither earlier entries nor historical ledger max_rounds4. Report filenames can use the authorized multi-digit round. Storage caps and outstanding result reservations still apply, so extension cannot promise unbounded storage or start inference without headroom. Thirty-two is the current structural ceiling; further extension requires an explicit storage design rather than resetting identity or history. The optional trusted local review helper accepts an explicit validated durable budgetSubject; without one it retains default4. Existing installed legacy cron workers remain capped until independently updated; the comment handoff supports the audited effective allowance.

Legacy operatorContinuations are counted alongside the unchanged implementation array. The first compatibility reservation is bound to the exact operatorTakeover nonce, subject membership and explicit history-preserving owner authorization, and grants only its already spent round. Further reservations require separate nonce-bound budgetExtensions and fresh reservation metadata, without copying terminal evidence or approvals. Intermediate implemented-awaiting-independent-qa remains active/unverified. A passed continuation requires its real tested subjectSha and relative evidence file. Revision adoption inherits the existing continuations and coordination from durable state, requires the new imported-history.json to bind the completed continuations, freezes their evidence in the new packet, and compares non-artifact source to the latest actual passed continuation. Manual owners remain in their original collection; ordinary adoption cannot create a second owner.

Pinned trees and file digests are memoized only during an operation. CLI submit/import/label projection shares one operation; mutable head/base/merge-base/open/auth/check/feedback observations remain fresh at mutation guards. A failed standalone write reloads validated authoritative state before normal-batch processing, so unsaved QA or approvals cannot ride on another entity's save. Transient read failures leave the waiting phase unchanged.

A label failure after durable state persistence exits nonzero with persisted=true, projection=failed and next=reconcile --pr N. Reconciliation converges labels without another report, claim or model call. Only idempotent label POST/DELETE operations have bounded backoff retries; state writes retry/rebase only on confirmed409. A definite non409 write failure uses state-write-failed; timeout/lost receipt uses state-write-uncertain and requires authoritative reconciliation before retrying. Diagnostics contain owned codes and phase information, never raw stderr or credentials.


### External authorization boundary and current integration limits

New budget extensions, failed-review retries and reservation releases use an injected `authorizationVerifier`. The trusted embedding must observe the actual authenticated user instruction or independently verify an external maintainer source, check exact repository/collection/entity/PR-or-issue/actor/action/current-SHA/history/budget/reservation bindings, and atomically consume one action nonce. A durable user-session grant may authorize continued work until resolution: the same GitHub account is allowed, and each consumed round remains separately reserved and spent. Repeated user approval and a second human are not intrinsic budget requirements. The default allowance remains four when no verified grant exists; storage ceilings still apply. Old takeover, extension and continuation records retain their original bytes and legacy provenance, rather than being relabeled as independent native human approval.

A trusted host can attest that the actual agent stopped and that the known reservation nonce belongs to that stopped operation, under the already observed user grant; this does not require another user prompt. The verifier is a trusted host capability, not a JSON file, environment flag, signing key invented by this controller, or a free-text authorization reference. The stored digest binds receipt content; it does not authenticate its origin. The reference identifies a source the host actually checks. The CLI deliberately has no configured live session-log/comment-verifier integration in this repository, so new authorization-dependent actions fail closed until a trusted host injects that integration. Fixture verifiers demonstrate protocol behavior only; they are not live integration proof or native human approvals. A distinct-maintainer-comment verifier is an optional alternative requiring a real external check, not a default fabricated receipt.

Issue-only manual maintenance owners retain `pr: null` and their actual `reviewIssue`/issue cohort. A new issue allowance must bind `collection: manualBatches`, exact entity and real issue plus authorization; it cannot invent a PR or grant standalone/clinical merge authority. Every old failed attempt stays consumed.

Read failures are classified using positive GitHub HTTP status evidence: 408/429/5xx, explicit timeout and positively identified rate-limited 403 are retryable; other 4xx are durable rejection. Unknown stderr numbers do not establish an HTTP status or retryability. Mutations (including body-driven default POST), idempotent projections and merges have distinct operation metadata; uncertain mutation outcomes are reconciled before another write. Only finite safe code/status/phase diagnostics cross this boundary; raw provider stderr is discarded because it may contain clinical payloads. Standalone retryable reads record a bounded counter, current SHA and short per-subject backoff, and block at three consecutive failures. Success or changed SHA resets the counter; unrelated subjects continue against refreshed canonical objects. Failed persistence halts the entire mutation pass.

A durable `comment-requested` notice can be repaired with `node agent-team/src/bug-pipeline/review-handoff-cli.mjs reconcile --pr N`. Repeated request/reconcile queries the authenticated exact-body notice before posting, preserves requester/request ID/round and creates no ledger row. A notice that committed before a transport timeout is reused. Changed owner/head/request or revoked authorization fails closed.

All release eligibility, labels, CLI counts and dashboard counts use effective implementation attempts, including operator continuations. Running and awaiting-independent-QA continuations never project a ready review label. Historical-prefix arithmetic and immutable evidence comparisons intentionally retain the original implementation array.
