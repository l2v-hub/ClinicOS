# Audit funzionale ClinicOS — 10 ottobre 2026

L'audit delle correzioni e delle funzionalità della web app RSA ha riprodotto **sei difetti applicativi** e **due lacune nella copertura automatica**, registrati nelle issue #433–#440. Le correzioni precedenti sono pubblicate nel branch `codex/resolve-open-issues` e nella [PR #431](https://github.com/l2v-hub/ClinicOS/pull/431). Il merge e il deployment di produzione non sono attestati da questo controllo.

## Codice e ambiente verificati

Codice applicativo verificato: `155810e33151608954d3c5c23dd81d09df8cad44`; comprende le correzioni degli issue #405, #408, #410, #416 e #429, le modifiche PowerShell locali e l'aggiornamento del test browser d'importazione. I nuovi script di audit e questo rapporto aggiungono evidenze e riproduzioni, senza correggere i difetti appena scoperti.

Tutte le scritture dell'audit avvengono su PostgreSQL 16 locale, con database nuovi e identità/documenti sintetici. La navigazione browser usa cinque identità del simulatore (admin, supervisore, medico, infermiere, OSS). Il runtime AI è locale con provider `mock` per ogni ruolo. Nessuna chiamata di scrittura a produzione o dato clinico reale.

Stack dell'audit: Node 24.19, npm 11.9, Chromium di sistema, Vite e backend compilato; runtime Python con FastAPI/Pydantic/OpenAI SDK e stub locali. La CI usa il proprio Node 20 e Python 3.11. Database `clinicos_qa_audit`: API sui porti 3101/3102 e frontend 5175/5176. I test DB opt-in usano un secondo cluster PostgreSQL 16 dedicato sul porto 5434, con le protezioni previste dai test mantenute attive.

## Riproduzione e artefatti

Artefatti curati: [`artifacts/task-validation/functional-audit-2026-10-10`](../artifacts/task-validation/functional-audit-2026-10-10/). JSON API con tutti i controlli e quattro fallimenti; JSON browser con 92 viste e le risposte negate; screenshot OSS, cambio sessione e intake completato; log runtime/DB; JSON di copertura Python; patch dell'overlay temporaneo per la fixture archivio. I log non contengono token di sessione. Le tracce browser complete locali non sono incluse in Git.

Prerequisiti: DB locale **nuovo e isolato**, migrazioni applicate e seed sintetico; backend compilato con `AUTH_MODE=demo`, `ROLE_SIMULATOR_ENABLED=true`, `NODE_ENV=development`, `CLINICOS_ENV=development`, frontend collegato allo stesso backend e runtime mock. I nuovi script rifiutano URL di primo livello non locali; il responsabile del run deve anche controllare che `DATABASE_URL` indichi il DB sintetico. Le API scrivono solo dati sintetici ma conservano gli oggetti immutabili nel DB dell'audit.

```sh
QA_BACKEND_URL=http://127.0.0.1:3101 node e2e/qa-functional-api.mjs /tmp/clinicos-functional-api
QA_BACKEND_URL=http://127.0.0.1:3101 QA_FRONTEND_URL=http://127.0.0.1:5175 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node e2e/qa-functional-browser.mjs /tmp/clinicos-functional-browser
```

Nello stato verificato i runner API e navigazione terminano con codice 1: API per i quattro difetti confermati, browser per alert OSS/403. Non sono aggiunti alla CI come test verdi. Dopo le correzioni possono diventare regressioni.

Il controllo aggiuntivo di isolamento della sessione usa il paziente sintetico creato dall'audit API e la stessa pagina browser per medico → logout → OSS. Ritarda la consegna di risposte reali senza cambiarne corpo o status; prova il marker visibile nella GUI e la lettura corrente negata dal backend. Il runner termina con codice 1 per #440. Eseguire sul frontend Vite di sviluppo perché controlla anche la cache in memoria attraverso il modulo originale.

```sh
QA_SYNTHETIC_PATIENT_ID=<id-del-paziente-sintetico> QA_BACKEND_URL=http://127.0.0.1:3101 QA_FRONTEND_URL=http://127.0.0.1:5175 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node e2e/qa-session-isolation.mjs /tmp/clinicos-session-isolation
```

Il browser d'importazione usa un secondo backend sullo stesso DB sintetico con simulatore disattivato, `AUTH_MODE=demo`, `NODE_ENV=test` e l'operatore legacy del seed previsto dal test:

```sh
E2E_BACKEND_URL=http://127.0.0.1:3102 E2E_FRONTEND_URL=http://127.0.0.1:5176 QA_LOCAL_OFFLINE_FONTS=true PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium node e2e/import-happy-path.mjs /tmp/clinicos-import-browser
```

Per gli opt-in DB, usare solo il cluster sintetico e i nomi previsti dai guard dei rispettivi test: `clinicos_role_qa` con `BUG428_SYNTHETIC_CLUSTER` uguale al `data_directory` reale; `clinicos_sorting` con `ARCHIVE_DOCUMENT_DB_TEST=1`. L'overlay conservato negli artefatti è una prova diagnostica, non una modifica pubblicata del test originale.

## Limiti pratici

Non verificati dal vivo: Entra/tenant reale, provider OCR/LLM/STT, dispositivi medici, integrazioni esterne e comportamento della rete di produzione. Non eseguite prove fisiche con screen reader, guanti e luce intensa. Il browser verifica attributi accessibili, albero AX e uso della tastiera per le correzioni, non certifica un intero standard di accessibilità.

Nessuna percentuale di copertura JavaScript o funzionale è inventata; l'unica percentuale misurata qui riguarda gli statement del runtime Python. La knowledge base NHW e il numero di unit test non sono una misura di tutte le funzionalità. Il rapporto conserva fallimenti e aree parziali per rendere il lavoro successivo verificabile.
