## Audited continuation and trust-root changes

Default implementation/review allowance remains four. A maintainer may append one explicit durable allowance only through an injected trusted verifier of the actual external user session or independently checked maintainer source; a free-text reference, mutable receipt JSON or admin permission cannot supply that verification. The same GitHub account is allowed under a verified user-session grant, with a separately consumed action nonce for each allowance. The CLI has no configured live verifier integration and fails closed for these actions until a trusted host provides one; status exposes effective limits and consumed operator continuations. Preserve every prior attempt/report and the original group identity. A PR manifest, raw review comment or label cannot extend the budget or become an approval. Intermediate operator work remains unverified until independent QA and frozen exact-source evidence exist.

The comment channel proves the authenticated account and report binding, not that a particular model produced it. A reviewer sharing the PR-author or finalizer identity cannot alone authorize automatic merge. Controller, policy, instruction and workflow changes always require the manual protected path and an actual independent native human approving review. A missing/unreadable review-protection policy is a release prerequisite to diagnose, never permission for admin merge. Claim/QA/merge recovery is a separate maintainer command documented in docs/standalone-pr-review.md; reviewers do not edit durable state or release their own failed results into approval.


The review operating prompt and the tests pinning trust/authorization/budget policy are themselves human-protected trust roots and cannot auto-merge through an expanded allowlist. Recovery checks actual operation leases with the injected clock; `--force-live` requires an externally verified force capability. Merge recovery retains a tombstoned reservation for late receipt reconciliation. A resume fingerprint is deterministic state identity, not a random nonce. A missing request notice can be repaired idempotently by the trusted `reconcile --pr N` command without a new claim or round. Synthetic verifier tests do not prove a live session-log integration or native human approval.
