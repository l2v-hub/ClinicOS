## What was missing for invocability

1. A uniform, machine-readable catalog of capabilities → **CAPABILITY_CATALOG.json**.
2. One invocation contract (naming, schema, errors, identity, scope, hooks) shared by all
   capabilities → **`backend/src/tools/`**.
3. A transport for an orchestrator that carries the end-user identity → **`/tools`**.
4. Authorization/audit extension points independent from route code → **`tools/hooks.ts`**.
5. Proof that tool invocation reaches the same business outcome as the GUI → tool tests with
   GUI-parity cases.

## Risks observed (not fixed in Phase 1 unless listed in MIGRATION_PLAN)

- `POST /appointments` does not check the patient's scope (pre-existing; tool mirrors the route).
- `ensureOperator` silently provisions User/Operator rows for unknown operator ids.
- Diary `PUT`/`DELETE` have no author check and no audit.
- `/operators` POST/PUT accept unvalidated bodies.
- Idempotency store and rate limiters are in-memory (single instance).
- Documents route in Entra mode has facility-wide scope; tools apply ownership scope (stricter).
