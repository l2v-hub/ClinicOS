# Info without clicks — discovery audit (read-only)

Owner principle: _a slot or card occupied by something must show WHAT occupies it (drug, dose, everything) without an extra tap. Tablet-first: no hover-only info._

Date: 2026-10-03 · Branch: `fix/389-facility-resident-scope` (worktree as-is) · Read-only: no source file changed.
Runtime: own local stack (backend :3102, vite :5202, embedded PG `disc_info`, seeds `seed-assistant-demo` + `seed-phase10-demo`), Playwright, role «Infermiere 1», viewports **1180x820 (L-\*)** and **820x1180 (P-\*)**. Servers stopped afterwards.

Severity: **S1** = clinically relevant info (drug/dose/status/late/allergen) hidden behind a tap or invisible · **S2** = useful operational info hidden, or a counter instead of content · **S3** = cosmetic or secondary truncation.

### 1.2 Data available without new backend

- `GET /patients/:id/therapies/page?status=attiva` (`lib/patientTherapyCalendarRead.ts`), type `PatientTherapyAPI` (`types.ts:1153-1184`): `farmacoNome`, `dosaggio` (e.g. "20 mg compressa"), `viaSomministrazione`, `tipo`, `dataInizio` / `dataFine`, `giorniSettimana`, **`prescrittore`**, **`note`**, **`commercialStrengthValue` / `commercialStrengthUnit`**, `pharmaceuticalForm`, `schedules[]` (`time`, `fascia`, `quantityNumerator/Denominator`, `administrationUnit`).
  → strength is computable in the frontend: `computeEquivalent(num, den, strengthValue, strengthUnit)`, already used in `TerapiaFarmacologicaTab.tsx:161-167` (the "· 500 mg" pill). `buildPatientTherapyDay` throws away `prescrittore`, `note`, strength and `dataFine` (`lib/patientTherapyCalendar.ts:84-89`).
- `GET /therapy-slots?date=YYYY-MM-DD` (already called by `PatientTherapySlotDetail.tsx:42` through `cachedGetJson`) and `GET /therapy-slots/page?date=` (used by the week calendar). `TherapySlot.patients[].administrations[]` (`types.ts:1071-1083`, built in `backend/src/therapies/therapy-slots.ts:347-355`) contains `drugName`, `dosage` (= quantityLabel ?? dosaggio), **`quantityLabel`** ("1 compressa — 500 mg"), `route`, `scheduledTime`, **`status`** (pending / administered / not_administered), **`administeredAt`**, **`administeredBy`**, **`notAdministeredReason`**. Plus `slot.summary`, `patient.room/bed/name`.
  → a patient-scoped helper already exists: `patientGiroTime(slots, patientId, time)` (`lib/therapyGiro.ts`).
- Not in any payload (would need backend): the administration **note** (free text when the reason is "altro"); prescriber and therapy note at slot level (join via `therapyId` against the therapies page instead, which works for the patient calendar).
- "Late" is computable client-side: `scheduledTime < facilityLocalMinute()` and `status === 'pending'`. This is the same rule as `lib/dashboardTherapies.ts` / `cellTone`.

**Conclusion: every field the owner asked for (drug, strength, quantity, route, time, status, who/when, reason, prescriber, note) is available to the frontend today. No new backend is needed.** The one exception is the free-text note on a non-administration.

### 1.3 Spec — what each event must show, per view and width

Common rules: no `title=` as the only carrier. Status shown as **text + color**, never color alone. Red only for late or not administered. Text wraps (no `nowrap` / ellipsis on drug, dose or status). The tap stays for **actions** (Somministra / Non somm.), not for reading.

**A. Patient calendar — day view (`PatientTherapyCalendar`)**
Data: join therapies page (by `therapyId` = event id prefix) with `/therapy-slots?date` (by patientId + `scheduledTime`), fetched once per date instead of only on tap.

| Width                               | Each event block must show, inline                                                                                                                                                                                                                                                            |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1180x820 (single row, full width)   | `08:00` · **Metformina** · **1 compressa — 500 mg** · orale · status chip: `Da somministrare` / `In ritardo 150 min` (red) / `✓ 08:12 · Rossi` / `Non somministrata · Rifiutata` · secondary line: `Prescr. Dr. X` · note (full text, wrapping) · `Una tantum` / `fino al 10/10` when present |
| 820x1180 (portrait, ~690 px usable) | same fields on 2–3 wrapping lines: line 1 time + drug + strength-dose; line 2 route + status chip; line 3 prescriber + note (wrap, no clamp)                                                                                                                                                  |
| ≤600 (phone, not required)          | same content stacked; nothing moves to a tooltip                                                                                                                                                                                                                                              |

The hour row must also show a compact summary when it has more than one dose ("08:00 · 2 dosi · 2 in ritardo"). Opening the detail must not re-list the drugs; it should only host the actions (or show actions directly on the event row for roles with `administration.confirm`).
Add a **week view** (7 columns x schedule times). Each cell lists every dose as "Metformina 500 mg ·1 cp" plus a status glyph and text (✓ / ✗ / ritardo). At 820 px use a 7-day agenda list (one day per block) instead of a 7-column grid, so names never ellipsize. Optional month view: per day "4/4 ✓" plus the late or missed drug names listed (no "+N").

**B. Ward week calendar (`TherapyWeekCalendar`)**
Data already fetched (`page.slots[].patients[].administrations[]`); today it only reads `summary`.

| Width                    | Each fascia x day cell must show                                                                                                                                                                           |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1180x820 (cells ~135 px) | counter `0/3` **plus a list of the doses**: `Nanni · Metformina 500 mg` + status word (`ritardo`, `✓`, `non somm.`). Sort late first, then pending. If more than ~4 rows, the cell grows taller (no "+N"). |
| 820x1180 (cells ~95 px)  | switch the layout to **day-stacked list** (one section per day, fascia rows inside, full patient · drug · dose · status lines). A 7-column grid cannot show drug names at this width without truncating.   |

**C. Giro rows (`TherapyGiroRows`)**: add `In ritardo di N min` (red) to pending items whose `scheduledTime` has passed. Drop the duplicate dose (name line = drug name, caption = quantityLabel · route).

**D. Agenda (operator + manager)**: wire `therapySlots` (`App.tsx:3432,3665`). In the 30-min row, the therapy card lists `patient · drug · strength-dose · status` per administration (same component as B). Week view shows the per-cell dose list as in B, instead of the "go to Terapia" note.
