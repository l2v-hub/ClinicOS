# Deep navigation audit — every patient entry point (read-only discovery, 2026-10-03)

Owner principle: every element that refers to a patient must land **directly** on the place of the
useful information (tab + sub-tab + item), never on the Panoramica.

Method: code-first (frontend/src, branch `fix/389-facility-resident-scope`). Runtime check was
attempted but **blocked**: port 3101 is held by a stale backend from another worktree
(`ClinicOSHouse-worktrees/capability-layer`, PID 25016, running since 2026-09-30, not ours, not
killed). DB `disc_nav` was created/migrated/seeded on 127.0.0.1:54339; my vite on 5201 was stopped.
All findings below are therefore **code evidence**, not browser evidence.

## How patient navigation works today

- Every entry point resolves to `selectPaziente(p, tab?)` / `selectPazienteById(id, tab?)` /
  `goToPazienteByNome(nome, id?, tab?)` (App.tsx:790/814/2816). The **only** target parameter is a
  `TabId`. No sub-tab, no item id, no date/slot.
- `PatientDetail` maps the TabId to one of 8 `CHART_SECTIONS` and, if the TabId is not the first part
  of its section, scroll-pins `[data-chart-part="<tab>"]` (PatientDetail.tsx:2361-2397).
- Item-level focus mechanisms **already exist but are internal only** (not reachable from outside the chart):
  - `therapyFocus` → `TerapiaFarmacologicaTab focusTherapyId` (row highlight + scroll, sub-tab
    attivi/sospese) — used only by Diario "apri terapia" (PatientDetail.tsx:2611-2614).
  - `archiveFocus` → `DocumentiTab focusDocumentId` — used only by assessment → archive.
  - `assessmentFocus` → `AssessmentWorkspace initialAssessment` — used only by archive → assessment.
  - Consegne feed `openConsegneFeed(query, focusId)` (App.tsx:776) — ward feed focus on one handover.
- No external sub-tab control: `TerapiaFarmacologicaTab` sub-tabs (`attivi | programmazione |
calendario | giornaliere | storico | sospese`, line 93) are local state; `TherapyRoundsPage` has no
  initial hour/patient/filter prop (selected hour = `initialGiroTime`).
- URL hash is `#/dettaglio-paziente/<id>` only (App.tsx:719): reload / shared link loses the section.
- Supervisore uses the admin shell (`ruolo === 'admin'`) → AdminDashboard; Medico/Infermiere/OSS use
  OperatorDashboard. OSS lacks `therapy.list`/`documents.list`: a deep link into Terapia/Documenti
  renders the "Sezione non disponibile" panel (PatientDetail.tsx:2800) instead of falling back.

**S2** = right section but not the item/sub-tab/view, or information is dropped on the way;
**S3** = minor / aggregate / affordance issue.

## Shared mechanisms that would fix most rows

1. **One patient-target API** — replace `(patientId, tab?)` with
   `openPatientAt({ patientId, tab, subTab?, itemId?, date?, slot?, anchor? })` in App.tsx, carried
   through `selectPaziente` → `PatientDetail` as a `navigationTarget` prop (bumped by
   `navigationRequestId`). Generalise the existing internal `therapyFocus` / `archiveFocus` /
   `assessmentFocus` states to be seeded from it. Fixes #1, 2, 5-7, 9, 11, 19-22, 32, 41, 45, 48.
2. **Sub-tab + item focus in Terapia** — `TerapiaFarmacologicaTab` accepts `initialSubTab`
   (`giornaliere`) + `date` + `focusTherapyId` + `fascia`; keep `therapyId` and `fascia` on
   `ScadenzaTerapia` (already in the source loop). Anomalies need therapyIds (or focus by drug name).
3. **Handover focus in the chart** — `consegnaId` highlight in `renderConsegne` (reuse the feed's
   `focusId` pattern), used by Adesso, admin urgent cards, feed "Apri cartella".
4. **A small target resolver** (`lib/patientTarget.ts`, pure): maps a domain signal → target
   (`therapy-late` → Terapia/giornaliere+slot; `consegna` → Clinica/consegne+id; `allergy` →
   diagnosi/allergie; `critical-vitals` → parametri; `risk:<tipo>` → module tab; `appointment:<tipo>`
   → note/esami), with a capability check and permitted fallback (#53). Make the chips/lines in #2, 3,
   20, 29, 43, 44 buttons that call it.
5. **Ward-page entry params** — `TherapyRoundsPage` `initialHour`/`initialFilter`/`focusPatientId`;
   `MultiPatientParametri` `initialFilter`; `PatientList` `initialView` + signal filters; KPI tiles pass
   them (#8, 12-16, 23-26, 37).
6. **Target in the URL/history** — encode tab (+item) in the hash and in `NavEntry`; store origin
   page sub-state (giro hour, consegne mode) in history state so Back returns to the exact origin
   context (#51, 52).
7. **Agnos/Assistant pass-through** — forward `recordId/documentId/pageNumber` and
   `patientId/patientTab` into `openPatientAt`; backend `classicScreen` for resident-bound skills
   should carry `patientTab` (#45-49).
