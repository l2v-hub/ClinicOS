# Protected-main demo secret scope remediation

This change adds a narrowly scoped, manually dispatched workflow for moving `RAILWAY_DEMO_TOKEN` from repository scope to the existing protected `glistening-friendship / demo` environment (`20880188544`). It targets only `l2v-hub/ClinicOS`, requires the fixed owner login `l2v-hub`, an exact reviewed main SHA/workflow/ref context, current main, admin identity, and the complete one-entry `main` branch policy. It does not alter environment policy.

The first fresh environment-bound job adds the environment copy only when it is absent, using the existing bound value over stdin and fixed CLI arguments. It never overwrites an existing environment copy. A second fresh environment-bound job requires a nonempty binding and verified environment inventory, then deletes only the repository copy and verifies both repository absence and environment presence. Unknown, incomplete, or unreadable secret inventories fail closed. A later non-environment negative probe must be a new run because GitHub binds repository secrets when a run is queued.

GitHub provides no conditional secret create/delete or compare-and-swap. The fixed workflow concurrency group serializes its own runs; safe operation also requires exclusive, cooperative operational ownership of this fixed secret while a run is active. Final inventories narrow the race and post-write checks detect observed drift, but cannot guarantee atomic protection against an uncooperative concurrent administrator.
