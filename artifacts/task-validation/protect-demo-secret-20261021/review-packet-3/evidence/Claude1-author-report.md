# PR #499 Claude finding: pin and verify the secret writer CLI

The actual medium finding on subject `561428ddab27578eb8b79b9eeb17c5e8fff44c6c` concerned the only environment-secret write path: it delegated path construction, public-key selection, and sealing to an unpinned runner-installed `gh`. The write remains delegated to `gh`, but each workflow job now obtains the fixed official GitHub CLI release `v2.103.0` and verifies its SHA-256 before use. The credential-free preflight and both environment-bound jobs each verify the installed binary version. The script requires the workflow-provided absolute binary path, independently checks `gh --version` with a stripped child environment, and only then starts the writer process with the existing value on stdin. A failed version check or mismatch returns a fixed error code before secret stdin is passed.

The public upstream evidence is pinned to CLI source commit `7948e8056e45ac3c729b829e0eafe2d0797a95c6`. In that source, the environment public-key GET and secret PUT both construct their routes using `safeurl.JoinPath`; the safe URL implementation applies Go `url.PathEscape` to each individual component and joins them with separator slashes. The release's own safe URL test asserts that spaces become `%20` and slashes inside a component become `%2F`. The fixed environment name therefore becomes `glistening-friendship%20%2F%20demo` as a single route component on both requests. The same pinned source maps the public-key response's `key_id` into `PubKey.ID`, uses that ID in the PUT payload, seals the plaintext using `box.SealAnonymous` with the returned public key, and Base64-encodes the ciphertext. Exact line links and source hashes are in `scripts/automation/evidence/gh-cli-v2.103.0.md` and the private `upstream-research/` records.

The official Linux AMD64 release archive is 15,030,338 bytes. Its SHA-256 `fdd768eb70f6409f80fcfa9f3a1c0adf0fc98d827ab3ce0bed2ac22762c5d786` was computed from the fetched asset and matches both the GitHub release API's asset digest and the official checksums file. The workflow downloads this exact release in the credential-free preflight and independently in each environment-bound job, verifies that digest, checks the binary version, and provides the absolute binary path to later steps. The installation steps themselves have no secret environment mapping.
