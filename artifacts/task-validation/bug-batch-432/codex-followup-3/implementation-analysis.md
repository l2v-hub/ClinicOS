# Recorded outcomes on ambiguous one-off prescriptions

Subject: PR483 source `bc90e86847de0bb17f06f0353c2f217e29eb5d14`, actual Claude round3 claim `4be71052-6784-40c3-8d85-3b4b990f8221`, changes-requested comment6255931219. This author delta addresses that recorded-outcome finding only; it supplies no parent approval or release claim.

The loader previously excluded every one-off lacking a schedulable band before reading its administration records. Verification items therefore lost the actual day outcome. Exact scheduled totals omitted those prescriptions, and assistant verification samples included them as unresolved.

The changed read model resolves one outcome for each therapy/patient/civil-date identity. An actual given record wins across legacy bands and duplicate rows; ties prefer a linked record, then ascending record id. Legacy matching stays patient/drug/date bound. A shared parameterized SQL resolver supplies the same outcome to exact counts, one-off page reads and assistant exclusion. A bounded extra loader query selects at most one day outcome per one-off, preserving the existing recurring legacy latest-record behavior. Modern record reads also bind patient identity. No schema, endpoint or administration write implementation changes.

Verification items remain untimed and unwritable, with null quantity/dosage and canAdminister=false. Optional recordedOutcome carries the actual record id, patient/therapy/date, administered or not-administered state, record operator, record timestamp and refusal reason. The timestamp uses confirmedAt when available, otherwise the stored updatedAt (refusals intentionally have no confirmedAt). The interface labels this the recording time; it is never used as a prescription time, band or dose quantity. Old responses without metadata remain unknown.

The verification group's exact summary separately counts administered, notAdministered and unrecorded, summing to total. Continuations keep bounded details and the first-page exact summary. Dashboard outcome totals include those recorded counts without making them actionable. Assistant pending and verification queues exclude already recorded one-offs. The shared verification panel renders actual outcomes after reload on both agendas, giro, week/calendar and drug details. The patient calendar now mounts that same panel for each already loaded visible day and current patient; it adds no request or scheduled row.

The strict parser rejects malformed/unknown record fields, mismatched patient/therapy/date, invalid timestamps or states, contradictory reason/status and inconsistent loaded/count metadata. Pagination rejects reassignment of a therapy to another patient. Missing metadata never becomes a false given state.

Write denial is preserved: ambiguous prescriptions still return409 and cannot create records.
